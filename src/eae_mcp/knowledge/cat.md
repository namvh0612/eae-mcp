# CAT — Composite Automation Type

A CAT is the EAE unit of reuse for **equipment**: a composite FB packaged with everything an operator needs.

## Files (catPump example; ~24 files in 3 projects)
| Project | Files | Role |
|---|---|---|
| IEC61499 | `catPump/catPump.fbt` | The composite FB (`Comment="CAT Function Block Type"`, `Format="2.0"`) |
| | `catPump/catPump.cfg` | **Manifest**: sub-CATs, HMI interface, `<Symbol>` (.NET) and `<WebSymbol>` (eHMI), plugin files, logical folder |
| | `catPump/catPump_HMI.fbt` | **HMI interface SIFB** (instance `IThis`): its inputs are the values shown in HMI, its outputs come back from HMI |
| | `_CAT.offline.xml`, `_HMI.offline.xml` | Offline parametrization |
| | `_CAT.opcua.xml`, `_HMI.opcua.xml` | OPC UA exposure per variable |
| HMI | `catPump/catPump_sDefault.cnv.*` | .NET symbol; `.cnv.xml` mirrors the HMI interface |
| | `catPump/catPump.def.cs`, `.event.cs`, `.Design.resx` | Generated from `_HMI.fbt` — never edit |
| WEB | `catPump/catPump_seDefault.sym.{json,ts,xml}`, `.user.cs` | eHMI symbol |

## How data reaches the HMI
1. Add the variable (e.g. `OUT1 : INT`) to `catPump_HMI` and associate it with an event (`REQ WITH OUT1`).
2. In the CAT network, `IThis.QI = TRUE` and trigger `IThis.INIT`.
3. Wire the value to `IThis.OUT1` and fire `IThis.REQ` when it changes.
4. In the symbols, bind a widget with `TagName`/`tagName = "OUT1"`.

## Sub-CATs and the Agile pattern (SE.Agile)
`acPlant_v1_0` = `fbPlant_v1_0` (Basic FB with the logic) + `HMI_Indication_*`/`HMI_Control_*` sub-CATs (one per HMI value) + `Broadcaster*`/`Listener*` CATs (publish/subscribe between equipment over adapters and MQTT) + `InitComponent`/`GetAssetName` helpers. Symbols bind sub-CATs by name (`"EXPLIM"`) or dotted path (`"Plant.Broadcaster_v1_0"`).

### Wiring of an Agile CAT (generated by `eae_agile_cat_create`)
| Part | How it is wired |
|---|---|
| IThis | only `AssetName` (HMI event `REQ` with AssetName) |
| Skeleton | `PLOAD → ResolvedAssetName(GetAssetName_v1_0).REQ`; `.CNF → Register(InitComponent_v1_0, ClassId 201 for application CATs).INIT` and `→ IThis.REQ`; `Register.INITO → logic.INIT`; `logic.INITO → Register.INIT_HMI`; `Register.HMI_READY → IThis.INIT`; `IThis.INITO → Start(EVENTCHAIN).ACK`; `Start.EO → PREQ` |
| Indication (logic → HMI) | logic Basic FB **plug** `aHMI_Indication_<T>_v1_0` named like the signal → block `HMI_Indication_<T>_v1_0`.`Indication`; in ST `X.Output := v;` + event `X.SET` |
| Control (HMI → logic) | block `HMI_Control_<T>_v1_0`.`Control` → logic **socket** `aHMI_Control_<T>_v1_0`; the logic reacts to `X.ONCHANGE`, reads `X.Input`, writes back with `X.Output` + `X.SET` |
| Each block | `X.PREQ → X.PLOAD` (loads Minimum/Maximum/Units/DecimalPlaces/Default parameters); on the `HMI_INIT` chain `Register.HMI_INITO → B1.HMI_INIT → … → Bn.HMI_INITO → Register.HMI_INIT` |
| References | Format 2.0: a pin with an `ID` is referenced by ID (`$Register.24` = HMI_INITO, `$FLOW.31`), otherwise by name |

`<T>` = Real (REAL), Bool (BOOL), Integer (INT), String (STRING[1024], indication only). `eae_agile_signal_add` adds
signals to an existing Agile CAT (block, adapter on the logic, wiring, chain) and lists the ST lines to add.
